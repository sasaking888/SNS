# Grokへの依頼ルール（毎回このファイルを添付する）

CHARGE OFFICE LP を修正するときは、**このファイルと `index.html` / `styles.css` を一緒に渡す**。
オーナーが書くのは「どこをどう変えたいか」だけでよい。ルールはこのファイルが担当する。

---

## 0. 最初に読むこと

このLPは**法人向けの受託案件**であり、公開後に景品表示法・個人情報保護法の対象になる。
見た目の変更は自由だが、**数字と法令に関わる文言は絶対に触らないこと**（§2）。

---

## 1. CSSの直し方 ← 最重要

**`styles.css` の末尾に新しいルールを追記しないこと。**

この方法を続けた結果、現在このファイルには修正パッチが30個以上積み上がり、
`!important` が460個を超えている。同じ箇所を何度も上書きし合っているため、
**新しく書いても効かない**ことがある（実際に起きた）。

### やること

- **該当するセレクタをファイル内から探して、その値を直接書き換える**
- 同じセレクタが複数箇所にあれば、**一番最後のものを書き換える**（それが効いている）
- 新しいルールをどうしても足す必要があるときは、**なぜ既存を書き換えられないのかを報告する**

### やらないこと

- ファイル末尾への追記
- `!important` の新規追加
- ファイル全体の書き直し（今までの修正が全部消える）
- 既存のクラス名の変更

## 2. 触ってはいけないもの

### 数字（1文字も変えない）

| 項目 | 正しい値 |
|---|---|
| 施術実績 | **グループ累計33万人以上**（「グループ累計」を省略しない。2026-07-29訂正: 旧12万人から更新） |
| 施術料 | **11,000円 / 1時間（税込）** |
| スタッフ出張費 | **1,100円（税込）** |
| 総額例 | **34,100円（税込）**（33,000＋1,100） |
| 1人あたり | **約2,300円**（出張費込みで計算） |
| 施術可能人数 | **3時間で15名**（1時間あたり5名） |
| 最低契約 | **スタッフ1名の派遣につき3時間から** |

- **新しい数字を勝手に計算して足さない。**（過去にAIが「33万人」「1人あたり2,200円」を捏造した）
- 「1人あたり」を計算し直すときは**必ず出張費を含める**。含めないと景品表示法の有利誤認になる

### 法令に関わる文言（変えない・消さない）

- **チェアの注記**: 「※専用の折りたたみチェアは契約時にご購入いただきます（スタッフ1名につき1脚・買い切り。月々の費用には含まれません）」
- **個人情報の利用目的**（フォーム内）: 「ご入力いただいた個人情報は、お問い合わせへの回答および無料トライアル・資料のご案内にのみ利用します。第三者に提供することはありません。」
- **資格の記述**: 「国家資格保有者が在籍しています」
  - **「国家資格者が施術します」はNG**（有資格者と無資格者が混在しているため誤認になる）
- **「税込」の表記**（総額表示義務）

### 使ってはいけない言葉

| 使わない | 理由 | 言い換え |
|---|---|---|
| マッサージ | 無資格者が含まれるため、あん摩マッサージ指圧師法にかかり得る | 整体／施術／ほぐし |
| 治る・治療・改善します | 医業類似行為の効果標榜 | ケアする／整える |
| 必ず・絶対・誰でも | 誇大表現 | — |
| 〜が向上します／〜が下がります | 因果が立証されていない（優良誤認） | 〜につながると言われています／〜を目指します |

**計測していない数字を書かない。**（例:「カンタン30秒入力」← 実際に計測していないので使えない）

## 3. 提出前に必ず自己検証する

**3つの画面幅で実際に表示して、下のチェックを通してから提出すること。**

| 幅 | 想定 |
|---|---|
| **320px** | 一番狭いスマホ（iPhone SEなど）。**崩れが最初に出る幅** |
| **375px** | 標準的なスマホ。**一番多くの人が見る幅** |
| **1200px** | パソコン |

### チェック項目

- [ ] **横スクロールが出ていない**（`document.documentElement.scrollWidth` が画面幅を超えていない）
- [ ] **ボタンが枠からはみ出していない**（特にヒーロー内のオレンジCTA）
- [ ] **ボタンの高さが44px以上**（それ未満は指で押しにくい）
- [ ] **見出しが1〜2文字だけ次の行に落ちていない**（例:「まずはお気軽にご相談か／ら」）
- [ ] **文字が3文字以下で折り返していない**（特にヒーロー内の3つのタイル）
- [ ] **フォーム入力欄が16px以上**（それ未満だとiOSで勝手に拡大する）

**日本語は文字幅が読みにくいので、計算だけで判断せず必ず表示して確認すること。**
「たぶん入る」で進めた箇所が実際は溢れていた、というのが過去に何度も起きている。

## 4. 変更を頼むときの書き方（オーナー向け）

### 悪い例

> オレンジのCTAを1.4倍にして

→ Grokは「その場所の入れ物が何px幅か」を知らないので、素直に1.4倍にしてはみ出す。**実際にこれで事故が起きた。**

### 良い例

> オレンジのCTAを大きくしたい。
> ただしヒーロー内の文字エリアは右46%を人物画像用に空けているので、
> 幅が足りないなら配置か文言のほうを調整してよい。

**制約（幅・文言の長さ・崩してはいけない並び）を一緒に伝える。**

### まとめて渡す

**修正は1件ずつ小出しにせず、まとめて渡す。**
1件ずつ投げた結果、パッチが30個に増えた。まとめれば1回で済む。

## 7. 最終チェックはジーナが行う

Grokの修正が終わったら、**最終版の `index.html` と `styles.css` をジーナに渡す**。
ジーナは以下を機械的に確認する。

1. 数字が §2 の表と一致しているか
2. 禁止語が入っていないか
3. 3つの幅で崩れていないか
4. 共通憲法のレビュー観点6項目

**納品直前ではなく、半日前には通すこと。**修正が必要になったときGrokへ戻す時間が要るため。
